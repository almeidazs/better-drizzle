`where` is shared by every read, `count`, `exists`, `update`, `delete`, and `upsert`. It is typed against your table's columns and relations.

## Equality shorthand

The simplest filter is a direct value - it means "equals":

```ts tab="better-drizzle" tab-group="orm"
await client.users.findMany({
	where: { active: true, name: 'Alice' },
});
```

```ts tab="Drizzle" tab-group="orm"
import { and, eq } from 'drizzle-orm';

await db
	.select()
	.from(users)
	.where(and(eq(users.active, true), eq(users.name, 'Alice')));
```

That is identical to the explicit form:

```ts tab="better-drizzle" tab-group="orm"
await client.users.findMany({
	where: { active: { equals: true } },
});
```

```ts tab="Drizzle" tab-group="orm"
import { eq } from 'drizzle-orm';

await db.select().from(users).where(eq(users.active, true));
```

Multiple keys are combined with **AND**.

## String filters

String columns accept equality, membership, and pattern operators:

```ts tab="better-drizzle" tab-group="orm"
await client.users.findMany({
	where: {
		name: { contains: 'ali', mode: 'insensitive' },
		email: { endsWith: '@example.com' },
	},
});
```

```ts tab="Drizzle" tab-group="orm"
import { and, ilike, like } from 'drizzle-orm';

await db
	.select()
	.from(users)
	.where(
		and(
			ilike(users.name, '%ali%'),
			like(users.email, '%@example.com'),
		),
	);
```

| Operator | Meaning |
| --- | --- |
| `equals` | exact match |
| `in` / `notIn` | value is (not) in a list |
| `contains` | substring match |
| `startsWith` / `endsWith` | prefix / suffix match |
| `mode` | `'default'` (case-sensitive) or `'insensitive'` |
| `not` | negate a value or a nested filter |

## Numeric and date filters

Numbers, bigints, and dates accept range comparisons:

```ts tab="better-drizzle" tab-group="orm"
await client.users.findMany({
	where: {
		id: { gte: 100, lte: 200 },
	},
});
```

```ts tab="Drizzle" tab-group="orm"
import { and, gte, lte } from 'drizzle-orm';

await db
	.select()
	.from(users)
	.where(and(gte(users.id, 100), lte(users.id, 200)));
```

| Operator | Meaning |
| --- | --- |
| `equals` | exact match |
| `in` / `notIn` | value is (not) in a list |
| `lt` / `lte` | less than / less than or equal |
| `gt` / `gte` | greater than / greater than or equal |
| `not` | negate a value or a nested filter |

## Boolean filters

```ts tab="better-drizzle" tab-group="orm"
await client.users.findMany({
	where: { active: { equals: true } },
});
```

```ts tab="Drizzle" tab-group="orm"
import { eq } from 'drizzle-orm';

await db.select().from(users).where(eq(users.active, true));
```

Boolean columns support `equals` and `not`.

## Null and negation

Nullable columns accept `null` directly, and any operator can be negated with `not`:

```ts tab="better-drizzle" tab-group="orm"
await client.posts.findMany({
	where: {
		deletedAt: null, // IS NULL
		title: { not: { contains: 'draft' } },
	},
});
```

```ts tab="Drizzle" tab-group="orm"
import { and, isNull, like, not } from 'drizzle-orm';

await db
	.select()
	.from(posts)
	.where(and(isNull(posts.deletedAt), not(like(posts.title, '%draft%'))));
```

## Logical operators

Combine conditions with `AND`, `OR`, and `NOT`. They nest arbitrarily:

```ts tab="better-drizzle" tab-group="orm"
await client.users.findMany({
	where: {
		AND: [
			{ active: true },
			{
				OR: [
					{ email: { endsWith: '@company.com' } },
					{ name: { startsWith: 'Admin' } },
				],
			},
		],
	},
});
```

```ts tab="Drizzle" tab-group="orm"
import { and, eq, like, or } from 'drizzle-orm';

await db
	.select()
	.from(users)
	.where(
		and(
			eq(users.active, true),
			or(
				like(users.email, '%@company.com'),
				like(users.name, 'Admin%'),
			),
		),
	);
```

<Callout title="Top-level keys are already AND-ed">
	You only need explicit `AND` when you want to group an `OR` next to other
	conditions, or to express the same condition on a field twice.
</Callout>

## Dropping to raw Drizzle SQL

When you need an expression the structured filter does not model, pass a Drizzle `SQL` fragment straight into `where`:

```ts tab="better-drizzle" tab-group="orm"
import { eq } from 'drizzle-orm';
import { users } from './schema';

const user = await client.users.findFirst({
	where: eq(users.id, 1),
});
```

```ts tab="Drizzle" tab-group="orm"
import { eq } from 'drizzle-orm';
import { users } from './schema';

const [user = null] = await db
	.select()
	.from(users)
	.where(eq(users.id, 1))
	.limit(1);
```

Anything that produces a Drizzle `SQL` / `SQLWrapper` is accepted, so you keep the full expressive power of Drizzle for the cases that need it.
