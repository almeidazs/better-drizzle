better-drizzle exports helpers that normalize database errors across PostgreSQL, SQLite, and MySQL, so you can classify failures without string-matching driver messages. See [error handling](/docs/advanced/error-handling) for end-to-end usage.

```ts
import {
	isDatabaseError,
	getDatabaseErrorInfo,
	isUniqueViolation,
	isForeignKeyViolation,
	isNotNullViolation,
	isCheckViolation,
} from 'better-drizzle';
```

## Predicates

Each returns a `boolean` and accepts an optional constraint name (or column name, for `isNotNullViolation`) to match a specific one.

| Function | Signature |
| --- | --- |
| `isDatabaseError` | `(error: unknown) => boolean` |
| `isUniqueViolation` | `(error: unknown, constraint?: string) => boolean` |
| `isForeignKeyViolation` | `(error: unknown, constraint?: string) => boolean` |
| `isNotNullViolation` | `(error: unknown, column?: string) => boolean` |
| `isCheckViolation` | `(error: unknown, constraint?: string) => boolean` |

```ts
try {
	await client.users.create({ data });
} catch (error) {
	if (isUniqueViolation(error, 'users_email_unique')) {
		// handle duplicate email specifically
	}
	throw error;
}
```

## `BetterDrizzleError`

Every error thrown by better-drizzle itself is a `BetterDrizzleError` (it extends `Error`). Database failures that surface through an operation are normalized into the same shape.

```ts
import { BetterDrizzleError, BetterDrizzleErrorCode } from 'better-drizzle';

try {
	await client.users.findUnique({ where: { id: 1 } }).throw();
} catch (error) {
	if (
		BetterDrizzleError.is(error) &&
		error.code === BetterDrizzleErrorCode.ResultNotFound
	) {
		// error.status === 404
	}
	throw error;
}
```

### Static helpers

| Helper | Description |
| --- | --- |
| `BetterDrizzleError.is(error)` | Type guard, same as `error instanceof BetterDrizzleError`. |
| `BetterDrizzleError.from(error, overrides?)` | Normalizes any value. An existing `BetterDrizzleError` is cloned with the overrides applied. A value that looks like a database error (an object with a string `message`, `code`, or `sqlState`, or a numeric `errno`, which includes plain `Error` instances) becomes `DATABASE_ERROR` with the parsed driver, constraint, table, and column. Anything else becomes `UNKNOWN`. The original value is kept as `cause`. |
| `BetterDrizzleError.fromDatabaseError(error, overrides?)` | Always parses the value with `getDatabaseErrorInfo` and returns `DATABASE_ERROR` (unless `overrides.code` is set), with the parsed info under `details.database`. |

Instances also have `withCause(cause)` and `withDetails(details)`, which return a new error (details are shallow-merged), and `toJSON()`, which returns a plain object with every field except `cause`.

```ts
try {
	await db.insert(users).values(data);
} catch (error) {
	throw BetterDrizzleError.fromDatabaseError(error, {
		operation: 'create',
		table: 'users',
	});
}
```

`BetterDrizzleErrorCode` is an exported string enum. The status column is the default `status` for each code; any code not given a specific status defaults to `500`.

## `BetterDrizzleTransactionRollbackError`

Thrown when a [transaction](/docs/advanced/transactions) is explicitly rolled back via `tx.rollback(reason)`. It extends `BetterDrizzleError` with code `TRANSACTION_ROLLBACK` (status `409`). The `reason` you pass is available as `error.reason` (also as `cause` and `details.reason`), and a non-empty string reason becomes the message:

```ts
import { BetterDrizzleTransactionRollbackError } from 'better-drizzle';

try {
	await client.transaction(async (tx) => {
		tx.rollback('duplicate email');
	});
} catch (error) {
	if (error instanceof BetterDrizzleTransactionRollbackError) {
		console.log(error.reason); // 'duplicate email'
	}
}
```
